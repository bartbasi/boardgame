**T-027-B1 (provider closes the database without awaiting): acceptable product code.** Riverpod's `onDispose` cannot await, and `appDatabaseProvider` is keepAlive, so it is disposed only when the root container goes away (app shutdown, hot restart, tests). After that nothing holds the store. A query that races the close either finishes or fails. A failure is caught by `_guard` and becomes `StorageFailure`, and SQLite's rollback journal keeps any interrupted transaction atomic. A "refuse work once disposal starts" flag would add a lifecycle state to the store and would not protect anything a user can reach. QA's fix is right: the test now polls up to 2 s for the failure. It still fails if the close never happens. I ran database_providers_test.dart 5 times on Windows: all passed. Optional hardening is R2-G1.
