**What changed**

- `app/build.yaml` (new): drift_dev options (`databases`, `schema_dir: drift_schemas/`, `test_dir: test/drift/`) for `dart run drift_dev make-migrations`.
- `app/lib/core/data/database/app_database.dart` (new): schema version 1.
  - `games`: `id` INTEGER autoincrement primary key (internal surrogate id), `bgg_id` INTEGER nullable UNIQUE with CHECK `bgg_id > 0`, `details_json` TEXT nullable (the backend's details JSON as saved), `fetched_at` and `last_viewed_at` INTEGER nullable (UTC epoch milliseconds through `EpochMillisConverter`).
  - `barcode_matches`: `gtin13` TEXT primary key with CHECK "13 ASCII digits", `game_id` INTEGER NOT NULL REFERENCES games(id), `confirmed_at` INTEGER NOT NULL.
  - `beforeOpen` turns on `PRAGMA foreign_keys`. No table uses `bgg_id` as its key (decisions.md 2026-10-11, "Storage keys").
- `app/lib/core/data/database/open_app_database.dart` (new): `openAppDatabase()` uses `drift_flutter`'s `driftDatabase`, which runs SQLite in a background isolate (`NativeDatabase.createBackgroundConnection`), file `board_game_collector.sqlite` in the application support directory. Opened lazily on first query.
- `app/lib/core/data/database/local_game_store.dart` (new): `LocalGameStore`, the data-layer store that T-029's repository will use. Methods take and return `bggId`; the internal id never leaves the class. Every method returns `Result` and never throws (`_guard` turns any error into `StorageFailure` and logs only the operation and error type in debug builds).
  - `saveDetails(bggId, detailsJson, fetchedAt, viewedAt?)`: upsert on `bgg_id` (same row and internal id on repeat saves), then eviction.
  - `readDetails(bggId)`, `markViewed(bggId, at)`.
  - `saveConfirmedMatch(gtin13, bggId, confirmedAt)`: creates a details-less game row when needed, replaces any earlier match for the code, then deletes games that have neither details nor a match.
  - `readConfirmedMatch(gtin13)`.
  - Eviction: cap `defaultMaxCachedDetails = 500` [ASSUMPTION]. Over the cap, the details of the least recently viewed games are cleared (recency is `last_viewed_at`, or `fetched_at` for a game never viewed; ties go to the lower internal id). The game just saved is never the one evicted. A game a confirmed match points to keeps its row and `bgg_id`; other evicted games are deleted. M3 will add the collection exemption.
- `app/lib/core/data/database/database_providers.dart` (new): `appDatabaseProvider` (keepAlive, closes on dispose) and `localGameStoreProvider`. Generated files committed.
- `app/lib/core/domain/failure.dart`: new `StorageFailure` (sealed case); `isRetryable` in `failure_mapper.dart` returns false for it. Copy mapping in the failure test: `common.errorGenericBody`.
- `app/drift_schemas/app_database/drift_schema_v1.json` and `app/test/drift/app_database/generated/` (new): exported schema and migration helpers from drift_dev.
- `app/test/helpers/test_database.dart` (new): `inMemoryDatabase()` and `FailingInterceptor` (a failing fake that throws SQLITE_FULL for every statement once switched on).
- `app/README.md`: steps for a schema change.

**Known gaps**

- `app_database.dart` shows 44.4% line coverage: the table column getters are a declaration language that drift_dev reads at build time; drift never calls them at runtime (calling them throws). The schema they declare is proven by the PRAGMA tests and the exported-schema comparison. The gate passes; no ignore markers were added.
- Invalid input (BGG id below 1, GTIN key that is not 13 digits) gives `StorageFailure` from the CHECK constraints, not a separate failure. Callers pass contract DTO ids and `Barcode.gtin13`, so this should not happen in practice.
- Nothing in the app uses the store yet; T-029 wires it into the games repository.
- The Android and iOS builds with the sqlite3 build hook are proven only by CI (no emulator was used).

## Proposed decisions

1. On-device cache cap: 500 games with cached details, evicted by least recent view (fetch time when never viewed); the game just saved is never evicted. Keep [ASSUMPTION] until the user confirms the number.
2. Times in the on-device database are stored as UTC epoch milliseconds.
3. The database opens through drift_flutter's background isolate; a database error is the non-retryable `StorageFailure`.
4. Schema changes follow app/README.md "On-device database": bump the version, run make-migrations, commit the export and helpers, extend the migration test.
