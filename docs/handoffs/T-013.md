## Round 1

### Developer notes (flutter-developer)

#### What changed

- `lib/core/domain/` (pure Dart, new): `result.dart` (sealed `Result<T>` with `Ok` and `Err`, plus `fold`, `map`, `flatMap`, `valueOrNull`, `failureOrNull`; it re-exports `failure.dart`) and `failure.dart` (sealed `Failure`).
- Failure cases: `NoConnectionFailure`, `TimeoutFailure`, `RateLimitedFailure({Duration? retryAfter})`, `ServiceUnavailableFailure`, `NotFoundFailure`, `InvalidInputFailure(InvalidInputCode code)`, `UnexpectedFailure`, the seven from AC1, plus three more (see Proposed decisions): `AccessDeniedFailure` (401, 403), `CancelledFailure` (the caller cancelled), and `ConfigurationFailure(ConfigurationProblem)` (bad `API_BASE_URL`, AC3). Value equality by type and fields; `toString` shows only the type and fields.
- `InvalidInputCode` is a domain enum that mirrors the input codes of api_contract's `ErrorCode` (`invalidBarcode`, `invalidQuery`, `invalidBggId`, `unknown`), so domain code does not import api_contract. The data layer maps one to the other.
- `lib/core/data/network/` (new):
  - `api_config.dart`: `ApiConfig.parse(raw, allowInsecureHttp:)` returns `Result<ApiConfig>`. It refuses empty, relative, non-http(s), query, fragment, and user-info URLs, and http when `allowInsecureHttp` is false. It strips trailing slashes. `ApiConfig.fromEnvironment` reads `--dart-define=API_BASE_URL`.
  - `retry_policy.dart`: `RetryPolicy` with the ticket's values (full jitter, base 500 ms, factor 2, cap 8 s, 3 retries, Retry-After cap 30 s, connect 10 s, receive 15 s, total 20 s) and `parseRetryAfter` (delta seconds or HTTP date; a past date gives zero; a huge number is clamped so it still means "do not retry").
  - `failure_mapper.dart`: `decodeJsonObject` (null for invalid JSON or JSON that is not an object), `failureForStatus`, `failureForError` (every `DioExceptionType`), and `isRetryable`.
  - `api_client.dart`: `ApiClient.get` and `ApiClient.post` return `Future<Result<T>>` and never throw. Responses are read as plain text (`ResponseType.plain`, every status accepted, redirects not followed), then the client decodes them itself: 2xx must be a JSON object before `decode` (an api_contract `fromJson`) runs; anything else maps by status. Only GET is retried. A timer enforces the 20 s total budget and cancels the in-flight request. An optional dio `CancelToken` lets callers cancel (for search as you type later). Paths must start with a single `/`, so a request can never go to another host.
  - `http_log_interceptor.dart`: logs only `HTTP <method> <path> -> <status or error type> (<ms>)`. Never bodies, headers, or query strings.
  - `api_client_provider.dart` (+ `.g.dart`): the keep-alive Riverpod provider. Debug builds allow http and log; profile and release builds require https and add no log interceptor (`kDebugMode`).
- `android/app/src/main/AndroidManifest.xml`: declares `android.permission.INTERNET` (AC14, T-012 review R1-G5).
- `test/architecture/domain_purity.dart`: now also checks `lib/core/domain/`, and treats an import of `lib/core/data/` from domain code as a violation. Two new fixtures prove it (`core_domain`, `core_data`).

#### Status mapping and retry rules

| Status or error | Failure | GET retried |
|---|---|---|
| 2xx with a JSON object that decodes | Ok | n/a |
| 2xx with invalid JSON, a non-object, or a decode error | Unexpected | no |
| 400, 422 | InvalidInput (code from the error envelope, else `unknown`) | no |
| 401, 403 | AccessDenied | no |
| 404, 410 | NotFound | no |
| 408 | Timeout | yes |
| 429 | RateLimited (with Retry-After if readable) | yes, unless Retry-After is over 30 s |
| 502, 503, 504 | ServiceUnavailable | yes, unless Retry-After is over 30 s |
| 500, 501, other 5xx, 3xx, other 4xx | Unexpected | no |
| connection error, `SocketException` | NoConnection | yes |
| connect, send, or receive timeout; 20 s budget used up | Timeout | yes (budget permitting) |
| cancel | Cancelled | no |
| bad certificate, transform timeout, anything else | Unexpected | no |

A retry waits for Retry-After when the response has one (at most 30 s), otherwise for the jittered backoff. If the wait would end at or after the 20 s deadline, the call returns the last failure at once instead of waiting.

#### Known gaps

- No screen uses the client yet, so there is no Failure to copy mapping in presentation. The exhaustive switch in failure_test.dart sketches one with copy.md keys; the first screen that shows network errors should add the real one in lib/core.
- `ApiClient` has `get` and `post` only. Other methods can be added the same way when an endpoint needs them.
- No connectivity check: when the device is offline, a GET retries its connection error up to 3 times (about 1.75 s of waiting on average, at most 3.5 s) before returning NoConnection. A later offline ticket can skip retries when the OS reports no network.
- Status mapping beyond what the ticket names (401 and 403, 408, 410, 422, 500, 502, 504) is my proposal; the server (T-008) has not fixed its status codes yet.

### Proposed decisions

1. Failure hierarchy: the seven AC1 cases plus `AccessDeniedFailure` (401, 403), `CancelledFailure` (caller cancelled), and `ConfigurationFailure` (bad API_BASE_URL). Domain code gets the API error code through the domain enum `InvalidInputCode` instead of importing api_contract.
2. The status mapping and retry table above, including: retry GET on connection errors and timeouts as well as 429, 502, 503, 504; Retry-After honored on 503 as well as 429; when the next wait would pass the 20 s deadline, return the last failure at once.
3. Profile builds require https like release builds (`allowInsecureHttp: kDebugMode`).
4. `lib/core/domain/` is checked by the domain purity test, and domain code may not import `lib/core/data/`.
5. App tests read api_contract's JSON fixtures directly from `../packages/api_contract/test/fixtures/` instead of copying them, so they cannot drift.
