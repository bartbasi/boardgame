## Round 1

### Developer notes (backend-developer)

**What changed**

New pure Dart package `packages/api_contract/` (name `api_contract`, `publish_to: none`, SDK `^3.9.0`) with two DTOs built on freezed and json_serializable:

- `ErrorEnvelope { ApiError error }` and `ApiError { ErrorCode code, String message }`. JSON: `{"error": {"code": "...", "message": "..."}}`.
- `ErrorCode` enum, snake_case on the wire: `invalid_barcode`, `invalid_query`, `invalid_bgg_id`, `not_found`, `rate_limited`, `upstream_unavailable`, `internal_error`, plus client-side `unknown`. These are the codes T-008 and T-018 name, added now so T-008 can use `not_found` and `internal_error`. `ErrorCode.wireName` gives the wire string (handy for logs).
- `HealthResponse { String status, String version }` for GET /health. `status` is a plain string, not an enum, so T-019 can extend the body (database status) additively.
- `CheckedFromJsonException` is re-exported, so callers can catch decoding failures without depending on json_annotation directly.

Decoding behavior is set once in `build.yaml` (`checked: true`, `explicit_to_json: true`, camelCase keys): unknown fields are ignored, and a missing, null, or wrongly typed required field throws `CheckedFromJsonException` whose `key` names the field.

**Generated files: committed.** `*.freezed.dart` and `*.g.dart` are in git. Reason: app/ and server/ consume the package by path (T-004), and the server Docker build copies packages/api_contract/ and runs with the plain Dart image; committing the output means neither consumer, nor the image, has to run build_runner for this package. Verified that generation is deterministic across platforms: in the `dart:stable` linux/amd64 image (Dart 3.13.5) a fresh `dart run build_runner build` produced byte-identical files to the ones generated on Windows. Proposed CI step for T-011: run `dart run build_runner build` in packages/api_contract and fail on `git diff --exit-code`.

**Resource use:** not applicable (library only).

**Proposed decisions**

1. Generated freezed and json_serializable files in packages/api_contract are committed, and CI fails if regenerating changes them. (Reason above.)
2. The error body shape is `{"error": {"code", "message"}}` with snake_case codes; unknown codes decode to `unknown`.
3. Decoding failures surface as `CheckedFromJsonException` (json_serializable `checked: true`), re-exported by api_contract.
4. api_contract SDK constraint `^3.9.0`, deliberately below the dev SDK so the app and the server image chosen in T-008 are not forced onto the newest Dart. Tested only on Dart 3.13.5; T-011 may raise the lower bound if CI pins a newer SDK.

**Open questions**

None blocking. For T-011: the "generated files are current" check needs build_runner in CI for this package (about 40 s for the first AOT compile of builders).
