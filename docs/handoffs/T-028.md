## Round 1
### Developer notes (flutter-developer)

**Where the shared games data source lives**

`app/lib/features/game_detail/`. The game entities and the remote data source are used by scanner (lookup, title search), game detail, and collection; game_detail is the feature that owns "a game". Other features import `features/game_detail/domain/` (allowed by the domain purity allowlist) and T-029 builds its repository on `features/game_detail/data/`.

**What changed**

- `app/lib/core/data/network/api_client.dart` (AC7): the client now asks dio for `ResponseType.stream` and reads the body itself.
  - `maxResponseBytes`, default `ApiClient.defaultMaxResponseBytes` = 1 MiB (1,048,576 bytes) [ASSUMPTION: "1 MB" read as 1 MiB].
  - A `Content-Length` over the limit is refused before the body is read; the attempt's CancelToken is cancelled, which makes dio close the response.
  - Without a usable Content-Length (or with a false small one), the bytes are counted as they arrive; the chunk that passes the limit cancels the subscription and the attempt at once.
  - Both give `UnexpectedFailure`, which is not retryable, so there is no second request. This applies to error statuses too (an oversized 503 is not retried).
  - Bytes are counted after transfer decompression, so a compressed body cannot expand past the limit.
  - Text is decoded as UTF-8 with `allowMalformed: true`, which is what dio's plain response type did before.
  - Errors raised while the body streams (a reset connection) are wrapped in a `DioException` before `failureForError`, so a mid-body `SocketException` is still `NoConnectionFailure` and retried, as before.
- `app/lib/features/game_detail/domain/` (new, freezed, pure Dart):
  - `game_summary.dart`: `GameSummary` (bggId, name, yearPublished?, bggUrl).
  - `game_details.dart`: `GameDetails` (all detail fields; optional ones nullable; designers and publishers are lists, empty when BGG lists none; `fetchedAt` in UTC).
  - `barcode_lookup.dart`: `BarcodeLookup` (gtin13, status, games) and `BarcodeLookupStatus` (matched, candidates, none, unavailable, unknown).
  - `game_search_results.dart`: `GameSearchResults` (backend-normalized query, games).
  - Lists are unmodifiable (freezed default).
- `app/lib/features/game_detail/data/` (new):
  - `game_dto_mapper.dart`: DTO to entity functions. Imports api_contract `as api` (its `GameSummary` has the same name as the entity). `lookupStatusFromDto` is an exhaustive switch with no catch-all, per the 2026-10-13 rule.
  - `games_remote_data_source.dart`: `GamesRemoteDataSource(ApiClient)`.
    - `lookupBarcode(Barcode, {cancelToken})`: `GET /v1/lookup/barcode/{gtin13}`.
    - `searchGames(String query, {cancelToken})`: `GET /v1/games/search` with `q` exactly as given; dio encodes it.
    - `fetchGame(int bggId, {cancelToken})`: `GET /v1/games/{bggId}`.
    - Two guards beyond the AC, see Proposed decisions 2 and 3.
  - `games_remote_data_source_provider.dart` (+ `.g.dart`): `gamesRemoteDataSourceProvider`, keepAlive, built on `apiClientProvider`.
- `app/pubspec.yaml`, `app/pubspec.lock`: added `freezed_annotation` 3.1.0 (was already transitive through api_contract) and dev `freezed` 4.0.2. Both MIT (LICENSE files in the pub cache, Remi Rousselet). The stack in CLAUDE.md names freezed for models.

**Known gaps**

- The server endpoints do not exist yet (blocked on BGG), so everything is proved against the contract fixtures and the fake adapter only. Nothing ran against a real server.
- dio reads ahead into its own buffer between the response headers and the moment the client subscribes. On a real socket that gap is a few event-loop turns. The tests deliver one chunk per millisecond to model a network. A body that arrives faster than that could be buffered past 1 MiB by dio before the cap cuts it off, but never decoded.
- No repository or caching here; that is T-029.

## Proposed decisions

1. The shared games entities and remote data source live in `features/game_detail/{domain,data}`; other features import that domain.
2. The lookup answer must be for the code that was asked (`code` equals the request's gtin13), and details must be for the requested bggId; otherwise `UnexpectedFailure`. This keeps T-029 from storing a wrong confirmed match.
3. `fetchGame` with a bggId below 1 returns `InvalidInputFailure(invalidBggId)` without a request, matching what the backend would answer.
4. `BarcodeLookupStatus.unknown` (a status added after this app version) is kept as its own domain value; screens treat it as not confirmed (like candidates with games, like none without). T-029 must not store it as a confirmed match.
5. The response size cap applies to every response, including error statuses, and is never retried.
6. Domain entities use freezed (no JSON on entities; JSON stays in api_contract DTOs).
