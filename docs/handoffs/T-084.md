Written before coding, as AC1 asks. docs/api-research.md EBAY-11 does not record the query parameter name, the hash encoding, or the response content type. I read the official page through WebFetch on 2026-10-14 (it was not blocked this time): https://developer.ebay.com/marketplace-account-deletion

| Proposed id | Fact | Quote or close paraphrase | Confidence |
|---|---|---|---|
| EBAY-12 | The challenge GET is `GET https://<callback_URL>?challenge_code=123`. The query parameter is `challenge_code`, and its value is unique per request. No other query parameter or header is described. | "The challenge_code query parameter value will be unique for the request." | confirmed |
| EBAY-13 | The hash is SHA-256 over the three strings concatenated (challengeCode + verificationToken + endpoint), sent as a hexadecimal string. eBay's Python sample uses `hashlib.sha256(challengeCode+verificationToken+endpoint)` and `hexdigest()` (lowercase hex); the C# sample lowercases explicitly. Base64 is not mentioned. | "eBay will need to verify the hexadecimal string." | confirmed |
| EBAY-14 | The challenge response must have content type `application/json`, body `{"challengeResponse": "<hash>"}`, built with a JSON library so no byte order mark is added. | "The content-type header for this response must be set to 'application/json'." | confirmed |
| EBAY-15 | POST notifications are JSON with `metadata` (topic, schemaVersion, deprecated) and `notification` (notificationId, eventDate, publishDate, publishAttemptCount, and `data` with username, userId, eiasToken). Verifying the `x-ebay-signature` header (Base64, checked with the Notification API getPublicKey, key cached about an hour) is described with "should", not "must". eBay's SDKs answer 412 when the signature fails. | "the developer should verify that the eBay marketplace account deletion/closure notification is actually coming from eBay" | confirmed |
| EBAY-16 | Volume: many days have zero notifications; be ready for up to 1,500 a day. eBay resends an unacknowledged notification until it is acknowledged (no retry schedule given). eBay's sending addresses are not published. | "should be prepared to acknowledge up to 1500 notifications on any given day" | confirmed |
| EBAY-17 | The endpoint string in the hash must be the endpoint saved in the portal; the page gives no normalization rules (trailing slash, case, port). The endpoint must be "a URL owned by and/or accessible to the developer". | "your endpoint and verificationToken are values specific to your destination" | confirmed (normalization: unverified) |
| EBAY-18 | Data holders must delete the user's data "in a manner such that even the highest system privilege cannot reverse the deletion"; retention only for "specific and demonstrable legal requirements". | quoted | confirmed |
