### Developer notes, round 2 (backend-developer)

**What changed**

- **R1-M1 (must fix), one overall body deadline.** `server/lib/src/ebay/account_deletion.dart` `_acknowledge` no longer uses `Stream.timeout` (a gap between chunks). It listens to the body and starts one `Timer` for the whole body when reading starts: 10 s in total [ASSUMPTION] (`notificationReadTimeout`, same name and the same `readTimeout:` test hook, so QA's stalled-body test still compiles and passes). When the timer fires, the subscription is cancelled and the answer is 408 `request_timeout`; dart:io then closes the connection, because the body was not fully read. The 64 KiB cap stays (413, reading stops). A body stream error still goes to the error boundary (500), never a 2xx. A trickling client is now held at most 10 s per request, so 300 requests a minute from one address can hold at most about 50 connections at once.
- **Orchestrator decision, open question 2:** `ebayRateLimitPerMinute` is 300 [ASSUMPTION] (was 60). The doc comment, README, and server/.env.example say 300. AC5's text still says 60; PM confirms at sign-off.
- **R1-G1, canonical URL only.** `endpointUrlProblem` now also refuses a URL when `Uri.parse(url).toString() != url`, with the reason "it must be written in canonical form (...)". The specific reasons (http, localhost, internal IP, and so on) are checked first, so they keep their messages. This refuses an upper-case scheme or host, dot segments, empty user info, an empty port, and needless percent escapes (`%2D`, `%61`). A port, an IPv6 literal, and an `xn--` label still pass.
- **R1-G2, placeholder token.** I chose to comment out the two lines in server/.env.example, as deploy/.env.example already does. A copy of the file used unchanged leaves the endpoint off. `test/config/env_example_test.dart` (my T-008 test, not QA's) now reads commented `# KEY=value` lines as documented optional variables.
