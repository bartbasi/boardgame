4. Generated files (Riverpod `*.g.dart`, gen-l10n output) are committed, and CI checks they are up to date.
5. Domain code may import only non-UI `dart:` libraries, its own package (not a feature's data or presentation layer), and an allowlist of pure Dart packages: collection, equatable, freezed_annotation, json_annotation, meta. The architecture test enforces this, following own-package imports transitively. Adding a package to the allowlist is a reviewed change to `test/architecture/domain_purity.dart`.

#### Should fix

- **R1-S1** app/test/l10n/strings_test.dart:283-302. The hard-coded string check reads one line at a time, so it misses `Text(` followed by the literal on the next line, which is exactly how `dart format` wraps a long string (`Text(\n  'This is a long sentence...',\n)`). The test is the only automated guard for AC9 once more screens land, so its most likely miss is the common case. Fix: run the regex over the whole file text (the `\s*` already spans newlines), compute line numbers from match offsets, and add a self-test with a wrapped literal. Today lib/ is clean (checked by hand), so this is not a must fix.
- **R1-S2** app/lib/app/shell/app_shell.dart:83-106. In the rail layout, NavigationRail applies the leading safe area itself, but the content in `Expanded` still receives the full `MediaQuery` padding, including the leading inset the rail already used. Later screens that use SafeArea or ListTile insets will pad the leading side twice in phone landscape, and nothing in the shell guarantees the trailing inset (app-shell.md section 2: "Safe areas and cutouts are respected on all edges"). Fix: wrap the content in `MediaQuery.removePadding(context: context, removeLeft: <leading is left>, removeRight: <leading is right>, ...)` using `Directionality`, and add a widget test with `tester.view.padding` set for a landscape cutout. Low impact now because the placeholders do not use SafeArea.
- **R1-S3** app/test/app/shell/app_shell_test.dart:84 and app/test/qa/shell_edge_cases_test.dart:14. `_tapDestination` and `_tap` are the same helper written twice. Move one copy to test/helpers/pump_app.dart (for example `tapDestination`) so future shell tests share it.
- **R1-S4** app/test/app/shell/app_shell_test.dart:324 and 357. `semantics.dispose()` runs at the end of the test body, so any earlier failing expectation leaks the SemanticsHandle and flutter_test then reports a second, misleading failure. Use `addTearDown(semantics.dispose)` right after `ensureSemantics()`. Same pattern wherever QA tests add semantics checks later.
