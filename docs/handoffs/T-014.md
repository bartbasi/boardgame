## Round 1

### Developer notes (flutter-developer)

#### What changed

- `.github/workflows/app.yml`, four jobs:
  - `checks` (ubuntu-24.04): `flutter pub get --enforce-lockfile`, `dart format --output=none --set-exit-if-changed .`, `flutter analyze --fatal-infos`, `flutter test --coverage`, then the coverage gate. The coverage report (`lcov.info` and `summary.txt`) is uploaded as the `coverage` artifact on every run that is not cancelled, including failed ones.
  - `codegen` (ubuntu-24.04): `flutter gen-l10n` and `dart run build_runner build --delete-conflicting-outputs` in app/, `dart run build_runner build --delete-conflicting-outputs` in packages/api_contract/, then `git diff --exit-code` plus a check for new untracked files. Fails with an `::error::` annotation that says which commands to run.
  - `android` (ubuntu-24.04): Temurin 17 (same JDK as the dev machine) with the Gradle cache, then `flutter build apk --debug`.
  - `ios` (macos-26, arm64): `flutter build ios --no-codesign` (release mode). Runs only when `github.event_name == 'workflow_dispatch'` or on a push to `refs/heads/main`; pull requests and pushes to any other branch skip it.
- Triggers: push and pull_request with paths `app/**`, `packages/api_contract/**`, `.github/workflows/app.yml`; plus `workflow_dispatch`.
- `permissions: contents: read`. No secrets. Concurrency: a newer push to the same ref cancels the older run, except on main.
- Flutter version is set once, in workflow `env.FLUTTER_VERSION: 3.47.7`. The coverage minimum is `env.COVERAGE_MIN: 80`.
- Flutter is installed by `app/tool/ci/install_flutter.sh` instead of subosito/flutter-action. Reason: that action's composite steps use `actions/cache@v5` by tag, so pinning the action to a SHA would still pull an unpinned nested action (AC7). The script reads the official release index (storage.googleapis.com/flutter_infra_release), downloads the archive for the runner's OS and CPU, checks the SHA-256 from the index, and checks that `flutter --version` reports the requested version. Same approach as gitleaks in repo.yml.
- Coverage gate: `app/tool/coverage_check.dart` (pure Dart, no packages). Counts `DA:` lines from lcov for `lib/core/**` and `lib/features/*/{domain,data}/**`, leaving out `*.g.dart` and `*.freezed.dart`; fails below the minimum or when nothing is in scope. Total across all files in scope, not per file. In-scope files that no test loads are listed as warnings, not counted (see Known gaps).
- Pub cache: `actions/cache` on `~/.pub-cache`, keyed on OS, CPU, Flutter version and the hash of the lockfiles the job resolves (`app/pubspec.lock`; the codegen job also `packages/api_contract/pubspec.lock`), per docs/decisions.md 2026-10-12 (T-004).
- AC3 order: generated files are committed (decisions 2026-10-12), so the `checks` job runs no code generation; the separate `codegen` job regenerates and diffs in parallel. That keeps every ubuntu job well under 15 minutes.

#### Known gaps

- A file that no test imports does not appear in lcov.info at all. The gate lists such files as warnings instead of failing, because an abstract interface file with no executable lines is also missing from lcov even when a test imports it (checked on Windows with a probe file). So an untested concrete file in domain or data lowers nothing; reviewers still need to check that every repository and use case has tests. Option for later: a generated test that imports every file in scope.
- `pull_request` trigger and push-to-main iOS build are not proved by a run yet (see AC1 and AC6).
- Release signing for Android still uses the debug key (T-012 R1-G3); it belongs to the store ticket, not here.

#### Proposed decisions

- CI installs Flutter with app/tool/ci/install_flutter.sh (official archive, SHA-256 from the release index, version check), not subosito/flutter-action, so no unpinned nested action runs.
- The app coverage gate counts lib/core and the domain and data layers in total, excludes generated files, and warns (does not fail) on files no test loads.
- iOS CI builds in release mode (`flutter build ios --no-codesign`) on macos-26.
