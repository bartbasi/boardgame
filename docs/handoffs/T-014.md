Counts `DA:` lines from lcov for `lib/core/**` and `lib/features/*/{domain,data}/**`, leaving out `*.g.dart` and `*.freezed.dart`; fails below the minimum or when nothing is in scope. Total across all files in scope, not per file. In-scope files that no test loads are listed as warnings, not counted (see Known gaps).
- Pub cache: `actions/cache` on `~/.pub-cache`, keyed on OS, CPU, Flutter version and the hash of the lockfiles the job resolves (`app/pubspec.lock`; the codegen job also `packages/api_contract/pubspec.lock`), per docs/decisions.md 2026-10-12 (T-004).

#### Must fix

- **R2-M1** app/tool/coverage_check.dart:129-137 and 187-189 (`unloadedFiles`, `formatReport`): a file with `// coverage:ignore-file` passes and is reported as `no executable lines`.
  - Problem: `flutter test --coverage` uses coverage 1.15.1 with `checkIgnoredLines: true` (flutter_tools lib/src/test/coverage_collector.dart:123 and :187). In coverage, `hitmap.dart:225` (`if (ignoredLinesList == null) continue;`) drops every file whose source has a line matching `util.dart:65` (`//\s*coverage:ignore-file[\w\d\s]*$`). So the file is absent from lcov.info even though the imports test loads it. The gate treats any absent file as having no executable lines and prints `no executable lines: <path>`.
  - Why it matters: an untested repository or use case leaves the strict gate with one comment line, and the report states something false about it. That defeats the 2026-10-12 strict gate decision, and the reviewer's grep is the only defense. The server gate (T-011 round 3, `exemptionReason`) reports the same case as `coverage:ignore-file marker`.
  - Fix: read the source of every in-scope file absent from lcov. If it matches coverage's own `ignoreFile` pattern (copy the regex and cite it, as server/tool/coverage_gate.dart does), list it as `exempt: coverage:ignore-file marker`, separately from `no executable lines`. Better still for domain and data, fail on the marker, since the decision allows only generated files to be exempt. Add tests for both labels, and one where the marker is only mentioned in prose (no match, because of the `$`).

- **R2-M2** app/tool/coverage_check.dart:31-37 (`isInScope`) and 116-127 (`filesInScope`): generated files are exempt by name alone, and the exemption is never shown.
  - Problem: any file named `*.g.dart` or `*.freezed.dart` drops out of scope, out of the imports test, and out of the report. A hand-written library such as `lib/features/collection/data/collection_repository_impl.g.dart` is never counted, never loaded, and never mentioned.
  - Why it matters: the decision exempts only generated files. The server gate requires the name and the `// GENERATED CODE - DO NOT MODIFY BY HAND` header in the first lines (T-011 review R2-G1, fixed in T-011 round 3). The two gates should apply the same rule, and every exemption should appear in the output so a new one is visible in review.
  - Fix: treat a file as generated only when it has the name AND that header in its first five lines (same rule as the server gate). Treat a `*.g.dart` file without the header as in scope. Print every exempt file in scope with its reason (`generated`, `coverage:ignore-file marker`, `no executable lines`) on every run. Add tests: a renamed file without the header is in scope and fails when untested, and a real generated file is listed as exempt.

#### Should fix

- **R2-S1** .github/workflows/app.yml:80-83 and app/tool/coverage_check.dart:190-204: a failing gate shows only `##[error]Process completed with exit code 1.` in the run summary (run 38288990582). The reason (`FAIL: no test runs any line of ...`) is visible only in the step log. Print the failure lines as `::error::` annotations and append the report to `$GITHUB_STEP_SUMMARY` when it is set, as server/tool/coverage_gate.dart does (`stepSummary`). That way the person reading the PR checks sees why it failed, and the exemptions from R2-M2 are visible without opening logs.
- **R2-S2** app/tool/coverage_check.dart (`parseLcov`, `formatReport`): `// coverage:ignore-start` / `ignore-end` and `// coverage:ignore-line` also remove lines before the gate sees them. A start/end pair around a whole file gives `0/0`, which the report prints as `100.0%`, and it does not count as untested. At minimum, list in-scope files that contain any `coverage:ignore` marker (with a count) in the report, so a reviewer sees them without grepping. Also print `0/0` files as `n/a` instead of `100.0%`.

#### Suggestions

- **R2-G1** .github/workflows/app.yml:183-188: the iOS job has no `needs:`, so a main push or a manual run spends macOS minutes (10x rate) even when `checks` or `codegen` fail. `needs: [checks, codegen]` costs a few minutes of wall time and saves macOS minutes on red runs.
- **R2-G2** app/tool/ci/install_flutter.sh:28-46: the SHA-256 comes from the release index on the same host as the archive, so it detects corruption, not a tampered index. Optionally, pin the expected hashes for the two archives CI uses (linux x64, macos arm64) next to `FLUTTER_VERSION` and compare against both. Also add `--proto '=https'` to both curl calls so `-L` cannot follow a redirect to http.
- **R2-G3** app/tool/coverage_check.dart:143-171: a hand-written `part of` file in domain, data, or core would be imported by the generated test, which is a compile error. ### Developer notes (flutter-developer)

#### What changed

The gate now follows the same rules as server/tool/coverage_gate.dart (T-011), per docs/decisions.md 2026-10-12.

- **R2-M1 (fixed).** For every file in scope that is absent from lcov, the gate reads the file's source.
  - It uses package:coverage's own per-line patterns, copied with a citation (coverage 1.15.1, lib/src/util.dart lines 62 to 65).
  - A `coverage:ignore-file` marker in lib/core is exempt, reported as `coverage:ignore-file marker: <path>`.
  - In domain or data, the marker FAILS, unless the file is in `ignoreFileAllowlist` (a const map in the tool that needs a reviewed reason; it is empty).
  - Only an absent file without a marker counts as `no executable lines`. Given the imports test, that means a loaded library with no lines.
  - Prose that only mentions the marker does not match, because of the `$` in the pattern.
- **R2-M2 (fixed).** A file is generated only when it has the `*.g.dart` or `*.freezed.dart` name AND the `// GENERATED CODE - DO NOT MODIFY BY HAND` header in its first five lines (`isGenerated`, same as the server).
  - A renamed hand-written `.g.dart` is in scope: it is counted, imported by the imports test, and fails when untested.
  - Every exemption is printed on every run, under `Exempt files: N` with its reason. Today that is `generated (GENERATED CODE header): lib/core/theme/theme_mode_controller.g.dart`.
  - The path-only `isInScope` is kept for QA's tests and library callers. The CLI uses the header rule (`checkCoverage(..., generated: {...})`).
- **R2-S1 (fixed).** Every `FAIL` line is also printed as an `::error::` annotation. The report goes to `$GITHUB_STEP_SUMMARY` under "App coverage gate". The coverage gate step now runs even when a test failed (`if: !cancelled() && hashFiles('app/coverage/lcov.info') != ''`; flutter test still writes lcov.info), so the coverage reasons appear next to test failures.
- **R2-S2 (fixed).** Files with `coverage:ignore-start`, `ignore-end`, or `ignore-line` markers are listed with a count. A `0/0` file prints as `100.0%  0/0  <path>  (n/a, no executable lines left)`. The `100.0%  0/0` prefix stays because QA's test `record with SF but no DA lines adds nothing and does not divide` asserts that text. QA may change that assertion so the line can read just `n/a`.
- **R2-G1 (done).** The iOS job has `needs: [checks, codegen]`, so a red Linux run spends no macOS minutes.
- **R2-G2 (partly done).** Both curl calls use `--proto '=https'`. Not done: pinning the archive hashes. Two extra hashes would have to change with every Flutter bump, and the index already comes over HTTPS from Google's release bucket, with the installed version checked afterwards. Kept as a possible later hardening.
- **R2-G3 and R2-G4: not fixed, as instructed.**
  - G3: a hand-written `part of` file in a layer would be imported by the generated test and fail to compile, with a confusing error.
  - G4: tag pushes also run app.yml, which is harmless today. Add `branches: ['**']` if that is unwanted.
