### Developer notes (backend-developer)

**What changed**

- `server/Dockerfile`: three stages.
  1. `build` runs on the build machine's own platform (`FROM --platform=$BUILDPLATFORM`), resolves dependencies with `dart pub get --enforce-lockfile`, and cross-compiles with `dart compile exe --target-os=linux --target-arch=x64|arm64 -DAPP_VERSION=<pubspec version>+<GIT_SHA>`. Cross-compiling Linux arm64 and x64 is officially supported since Dart 3.8 on 64-bit Linux, macOS, and Windows hosts (https://dart.dev/tools/dart-compile, checked 2026-10-12). So the arm64 image builds without CPU emulation; only running it locally needs QEMU.
  2. `runtime-files` is the same pinned Dart image for the target platform. It has no RUN step, so nothing executes in it; the final stage only copies its `/runtime/` folder.
  3. Final stage `FROM scratch`: `/runtime/` (glibc loader and libraries, CA certificates, nsswitch.conf) plus `/app/server`, `USER 65532:65532`, `EXPOSE 8080`, exec-form `ENTRYPOINT ["/app/server"]` so the server is PID 1 and gets SIGTERM directly.
- Build arg `GIT_SHA` is required (7 to 40 lowercase hex characters). Without it the build fails with `T-009: build arg GIT_SHA is required: ...`. The pubspec version must be `MAJOR.MINOR.PATCH` (optional `-pre`), with no `+build` part, or the build fails with a clear message. The image is labeled `org.opencontainers.image.revision=<GIT_SHA>`.
- `server/Dockerfile.dockerignore`: a Dockerfile-specific ignore file. Docker uses it instead of a root .dockerignore because it sits next to the Dockerfile and carries its name (https://docs.docker.com/build/concepts/context/, "Dockerfile-specific ignore files", checked 2026-10-12). So no root file was needed. It is an allowlist: `*`, then only the two pubspecs, the two lockfiles, `server/bin/`, `server/lib/`, `packages/api_contract/lib/`, then re-excludes `**/.env`, `**/.env.*`, `**/.git`, `app`, `.claude`, `docs`, `**/.dart_tool`, `**/build`, `**/coverage`, and compiled artifacts.
- `server/tool/docker_build.sh`: wraps `docker buildx build -f server/Dockerfile` from the repo root, passes `GIT_SHA=$(git rev-parse --short=7 HEAD)`, and warns on stderr if server/ or packages/api_contract/ has uncommitted changes. Extra arguments go to buildx.
- `server/README.md`: new "Docker image" section (build, run, cross-compiling, GIT_SHA, health check limitation, base image upgrade).
- No Dart code changed. No new dependencies.

One digest covers build and runtime files, so they cannot drift.
- Cross-compile: build stage is `FROM --platform=$BUILDPLATFORM` and maps `TARGETARCH` amd64/arm64 to `--target-arch=x64|arm64` with `--target-os=linux`; any other arch fails loudly (automatic platform ARGs, https://docs.docker.com/reference/dockerfile/#automatic-platform-args-in-the-global-scope; Dart cross-compilation for Linux x64/arm64 since 3.8, https://dart.dev/tools/dart-compile, as quoted in the developer notes). The `runtime-files` stage has no RUN, so the foreign platform never executes anything.
- Layer order: pubspecs and lockfiles, then `dart pub get --enforce-lockfile`, then sources, then `ARG GIT_SHA`. A new SHA only invalidates the compile step. Path layout `server/` plus `packages/api_contract/` matches T-004.
- Version stamping: `GIT_SHA` required and validated as 7 to 40 lowercase hex; pubspec version validated with no `+build`; `-DAPP_VERSION=<version>+<sha>` passed as one quoted argument. The `\$(...)` in the error message reaches the shell as a literal (Dockerfile does not substitute variables in RUN shell form, the shell does). `set -eu` with `${GIT_SHA:-}` is correct.
- Final stage: `scratch` plus `/runtime/` and `/app/server` only, numeric `USER 65532:65532`, no ENV, no secrets (GIT_SHA is the only build arg and is not secret), exec-form ENTRYPOINT so SIGTERM reaches the Dart process as PID 1 (QA saw clean drain on `docker stop`). No `/tmp` in scratch; grep shows no `Directory.systemTemp` or file I/O in server/lib or server/bin today.
- Ignore file: allowlist with `*` first, re-includes, then re-excludes; last match wins (https://docs.docker.com/build/concepts/context/#dockerignore-files). `server/Dockerfile.dockerignore` sits next to `server/Dockerfile` and is named after it, which the same page says takes precedence over a root `.dockerignore`. `**/.env` and `**/.env.*` cover every .env file, including ones planted under allowed folders (QA planted four).
- docker_build.sh: `set -eu`, every expansion quoted (user path has a space), `"$@"` passed through intact, `exec` so the exit code is buildx's. ## Proposed decisions

1. The server image is cross-compiled on the build platform (`--platform=$BUILDPLATFORM` plus `dart compile exe --target-arch`), not built under QEMU.
2. The build version is `<server/pubspec.yaml version>+<GIT_SHA>`, with `GIT_SHA` a required build argument; `server/tool/docker_build.sh` is the documented way to build locally.
3. The image runs as the numeric user `65532:65532`.
4. The Dockerfile's ignore rules live in `server/Dockerfile.dockerignore` (allowlist), not in a root .dockerignore.

## Open questions

1. Licenses. The final image contains glibc (LGPL-2.1-or-later) and the Mozilla CA bundle (MPL-2.0) copied unmodified from the official Dart image. These came with the T-005 decision (scratch plus `/runtime/`) but are not MIT, BSD, or Apache 2.0. As long as the image only runs on our own VM and is not published, we do not distribute it. If T-011 pushes images to a public registry, that is distribution, and we should at least ship the license notices. Please confirm with the user and record it in docs/decisions.md.
2. Health checks in T-010. The scratch image has no shell, curl, or wget, so a Compose `healthcheck` cannot run a command in the server container. Options for T-010: (a) add a `--healthcheck` mode to the server executable that calls `http://127.0.0.1:$PORT/health` and exits 0 or 1 (no new dependencies, a few lines of Dart, needs tests), or (b) copy a static busybox into the image (adds a shell, GPL-2.0). I recommend (a). T-010 AC6 requires a /health health check, so this needs a decision before T-010.
3. Page size on the VM [UNVERIFIED]. I tested the arm64 image only under QEMU user-mode emulation, which uses the host's 4 KB pages. Some arm64 Linux kernels use 64 KB pages, and I have not checked which page size the Oracle Linux or Ubuntu images for Ampere A1 use, nor whether the Dart 3.13 AOT runtime supports 64 KB pages. T-071 should run the image on the real VM before anything else (it is a quick `docker run` plus `curl /health`). Not in docs/api-research.md; see Research notes.
4. `server/tool/test_linux.sh` still uses the `dart:3.13.5` tag without a digest. It is a dev tool, not a base image, so I left it; say if it should be pinned too.
