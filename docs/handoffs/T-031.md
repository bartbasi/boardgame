### Review (code-reviewer): CHANGES REQUIRED

Scope: `git diff main...HEAD` (7 commits, merge base 0ccfec9). Ticket text on main is unchanged since the branch started (checked with `git log -L`). One must fix (QA's B1); the rest of the ticket is in good shape: layering is right (screens take callbacks, only the router knows paths, domain untouched), every copy string matches copy.md, no em dashes or double hyphens, goldens are CI-rendered, and each criterion has a real test.

**Must fix**

- R1-M1 (T-031-B1). `app/lib/features/scanner/presentation/manual_entry_screen.dart:83-86` with `app/lib/app/navigation/app_router.dart:93`. `_submit` calls `widget.onSubmit` for every valid submit, and the router pushes every call. Two taps on Look up, or two keyboard actions, before the next frame push two LookupResultScreen routes (QA's 2 tests fail locally, confirmed). Why it matters: Back shows a second result, and from T-033 on each route starts its own lookup (two backend calls, two loading states).
  - Recommended fix: a screen-level guard tied to the push future, not router-level dedupe.
    1. Change `onSubmit` to `Future<void> Function(Barcode)` and have the router return the push: `onSubmit: (barcode) => context.push<void>(lookupResultPath(from, barcode))`.
    2. In `_ManualEntryScreenState`, add `bool _opening = false`. In `_submit`: `if (_opening) return;` first, then on `Ok` set `_opening = true`, `await widget.onSubmit(value)`, and in `finally` set `_opening = false` if `mounted`. The push future completes when the result route pops, so the screen stays locked exactly while its result is on top and unlocks after Back.
    3. No setState or disabled look is needed (the button keeps its enabled look, so goldens do not change).
  - Why not router-level dedupe: go_router has no "push in flight" state. Before the next frame `ModalRoute.isCurrent` is still true and `GoRouter.state` timing is an implementation detail, so a location check is fragile. It would also have to match `digits` and canonical forms. The screen owns the gesture, so it should own the guard. For T-033, key the lookup provider by `barcode.gtin13` (a family), so any second consumer shares one request. That is defense in depth, not the fix.
  - Tests: QA's two B1 tests must pass. Add one test proving the guard resets: submit, Back, submit again opens exactly one result.

**Should fix**

- R1-S1. `app/lib/app/shell/app_shell.dart:40-66, 108`. The bar hides while a text field has focus. PRD Q32 says "while the keyboard is open". Focus and keyboard differ on real devices:
  - Android: system Back with the IME open closes the keyboard but keeps focus, so the bar stays hidden with no keyboard.
  - iOS: `TextInputType.number` is the number pad, which has no action or Done key. Flutter does not unfocus on a touch outside the field on mobile (`editable_text.dart` `_EditableTextTapOutsideAction`: touch unfocuses only on web). So the bar is hidden for the whole visit.

  On manual entry Back still works, so this does not block the user here. On T-032 it will: search.md focuses the field on arrival at the Search root, so a compact user would have no NavigationBar on a top-level destination. AC8 is literally met (it says focus, as app-shell.md section 2 does). Fix, or record as an open question for UX and PM: hide only when `_textFieldFocused && MediaQuery.viewInsetsOf(context).bottom > 0` (the shell sits above the Scaffold that consumes the insets), and set `tester.view.viewInsets` in `app_shell_keyboard_test.dart`. Both pieces of wording should then follow PRD Q32.
- R1-S2. `app/lib/app/navigation/app_router.dart:57, 64`. Same race as M1 on the entry points: a double tap on "Enter barcode" (Scan) or the Search app bar action pushes two manual entry screens. Not tested. Guard it the same way (the Scan and Search screens are stateless, so a small shared helper in `lib/app/navigation`, such as a push that ignores calls while its previous push future is pending, may be simpler). Add a double-tap test.
- R1-S3. `app/test/features/scanner/presentation/manual_entry_screen_test.dart:543-551`. The phone landscape test checks `rect.right <= left + width * 0.6`, which passes for any column up to 60%, and for a column at 30%. With padding 24 the right edge is exactly `content.left + 24 + 0.55 * (content.width - 48)`; assert that with `closeTo(..., 1)`. Also, the test at line 532 is named "medium and expanded" but only pumps expanded; add medium or rename it.
