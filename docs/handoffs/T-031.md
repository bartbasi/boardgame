### Developer notes (flutter-developer)

The main implementation was written in an earlier, interrupted session on branch worktree-agent-a3086967b93efe114 (commit 3b9d3c9) and merged into this branch with an ordinary merge. This session checked it against every criterion and the spec, added the focus order test, and rendered the goldens on Actions.

**What changed**

- `app/lib/features/scanner/presentation/manual_entry_screen.dart` (new): the screen. Validates with `Barcode.parse` (T-026) on the device, no network. Valid: calls `onSubmit` (the router pushes the lookup result). Invalid: copy.md error under the field, focus kept, assertive announcement `manualEntry.errorAnnouncement`. Error shows only after submit and clears on the next edit. `manualEntryErrorMessage` maps `InvalidBarcodeFailure` to copy.md (length 0 gives `errorEmpty`; only `wrongLength` shows the count). Layout: 600 dp centered column on medium and expanded; leading 55% on phone landscape; scrolls.
- `app/lib/features/scanner/presentation/barcode_field.dart` (new): BarcodeField component. Numeric keyboard, `FilteringTextInputFormatter.allow([0-9])` (ASCII only, typed or pasted) plus `LengthLimitingTextInputFormatter(13)`, digit counter `manualEntry.digitCounter`, clear button while it has text, error line with an icon (not color alone), keyboard action "search" submits and keeps focus, larger `scrollPadding` so the submit button scrolls into view above the keyboard.
- `app/lib/features/scanner/presentation/lookup_result_screen.dart` (new): placeholder destination showing `lookup.title` until T-033.
- `app/lib/app/navigation/app_router.dart`: manual entry and lookup result are sub-routes of both Scan and Search (`/scan/manual`, `/search/manual`, `/<branch>/lookup/<digits>`), pushed so the bar or rail stays. The lookup route re-parses the code and redirects an invalid one to the branch root. "Scan instead" and "Search by title instead" pop manual entry, then go to that destination.
- `app/lib/app/shell/app_shell.dart`: on compact windows the NavigationBar hides while a text field has primary focus (FocusManager listener, `AppShell.isTextFieldFocus`) and returns when focus leaves. The rail never hides. Reusable by every later text field.
- `scan_screen.dart`, `search_screen.dart`, `core/widgets/placeholder_body.dart`: entry points. Scan placeholder has an "Enter barcode" button (`scanner.actionManual`); Search has a 48 dp app bar icon action (`search.actionManual`).
- `app/lib/l10n/app_en.arb` and generated localizations: all `manualEntry.*` keys, `scanner.actionManual`, `search.actionManual`, `lookup.title`, `itemEdit.clearField`.
- Goldens: 6 new manual entry goldens. The 8 existing app_shell goldens were re-rendered because the Scan placeholder now shows the "Enter barcode" button (expected change).

## Proposed decisions

- Pushed lookup flow screens (manual entry, lookup result) are sub-routes of both Scan and Search, so the user stays in the destination they started from.
- The compact NavigationBar hides whenever any text field has primary focus (shell-level, not per screen), so T-032 search and later forms get it for free.
