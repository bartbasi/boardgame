- R1-S1 (should fix, PM or wording, no code change needed) docs/backlog.md T-099 AC5 says the part file's lines are "counted under its library". The code counts them under the part's own path (coverage_check.dart:40 comment, report line `1/2  lib/core/owner_part.dart`), which is what lcov reports (see above), and the totals are the same. Why it matters: PM checks criteria literally and would otherwise see a mismatch. Also note that the AC5 proof uses synthetic lcov; no real part file has been through `flutter test --coverage` yet, so recheck the report on the first ticket that adds a hand-written part.
- R1-S2 (should fix, QA test) app/test/qa/coverage_gate_t099_edge_test.dart:50 "a range in a presentation file with no lcov entry is not a rule": presentation files are never in `scopeFiles`, so `errors` is empty whatever evaluateGate does with markers; the test passes on main and would pass if the domain/data restriction were removed. The lib/core case in the developer's test already guards the restriction. Fix: delete it, or change it to a lib/core file with markers and 0/0 and assert it passes and is listed with its count (which would fail if `isDomainOrData` were dropped).
- R1-G1 (suggestion) coverage_check.dart:141 compares against an invisible literal U+FEFF inside `'...'` (bytes EF BB BF in the source). It works, but it reads as `startsWith('')` in most editors and a reformat or copy could drop it. Use `'﻿'`. Same in the two tests that build BOM sources.
- R1-G2 (suggestion, policy) markers that cover every executable line except one still pass in domain and data (only the count is listed). If that matters later, the gate could print an `::warning::` for marker lines in domain or data. No action needed for this ticket.

The fix the message suggests still works (remove the marker); wording could say "no executable lines remain and the file has markers".
- R1-G4 (suggestion) `partOwner` maps `part of 'package:<any>/x.dart'` to `lib/x.dart` without checking the package name. A foreign package would not compile anyway, so this only affects the error text.
