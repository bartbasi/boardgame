### Developer notes (flutter-developer)

**What changed**
- `app/tool/coverage_check.dart`
  - R3-S1 (AC1, AC2): the verdict line is built by a new `verdictLine(result, ruleFailures)`. It starts with `FAIL` only when the numbers fail (nothing in scope, below the minimum, or untested files). With only rule failures it reads `Coverage 100.0% (18/18 lines), minimum 80% met; gate failed on 1 rule above.` (plural for more), so `annotations()` returns one `::error::` line per real problem. When the numbers and rules both fail: `FAIL: 64.3% (18/28 lines), minimum 80%; gate also failed on 2 rules above.` A pass still prints `PASS: ...`.
  - R3-G1 (AC3): in `evaluateGate`, a domain or data file that has ignore-start, ignore-end, or ignore-line markers, no ignore-file marker, and 0 executable lines (0/0 in lcov, or absent from it) fails with a message that names the file, the start/end markers, and `ignoreFileAllowlist`, unless it is allowlisted (then exempt with reason `coverage:ignore-start/end markers cover every line, allowlisted: <reason>`). In lib/core it passes as before and stays listed with its marker count. Files where markers cover only some lines are unchanged.
  - R3-G2 (AC4): `isInScope` and `checkCoverage` are `@visibleForTesting`. The gate now calls a new `coverageOf(lcov, minPercent:, generated:)` with the header-based generated set; `checkCoverage` is a test-only wrapper that keeps QA's existing tests working unchanged. No production code calls the path-only rule.
  - R2-G3 (AC5): new `partOwner(path, source)` finds a hand-written part file (first directive after comments and a BOM is `part of`) and resolves its library from a relative or `package:` URI. New `importTargets(sources)` replaces each part with its library in the generated imports test (deduplicated, sorted), so `--write-imports` output compiles. The report gets a `Part files` section with `part file: <path> (part of <library>)`; the part's lines are counted under the part's own path, as lcov reports them. A part that names its library by name (or a URI outside lib/) fails the gate with a message asking for `part of '<file>.dart';`. Generated `.g.dart` parts are still exempt first, by header.
  - `GateOutcome` gained `parts` and `withError()`; the CLI uses `withError` for a stale imports test.
- `app/pubspec.yaml`, `app/pubspec.lock`: `meta: ^1.18.3` as a dev dependency for `@visibleForTesting` (already locked as a transitive dependency at 1.18.3, BSD-3-Clause, checked in the pub cache LICENSE). Only the lockfile's dependency type changed.
- `.github/workflows/app.yml` (AC6): `push` has `branches: ['**']`, so tag pushes no longer run app.yml. `pull_request` and `workflow_dispatch` are unchanged.
- `app/test/coverage_imports_test.dart`: regenerated, no change (no lib files added).

**Known gaps**
- A part file whose library is outside the layers (for example in presentation) is loaded through that library; that is tested in `importTargets` only, since no such file exists.
- A `part of` directive preceded by metadata annotations (`@x part of ...`) is not detected; Dart code here never does that.

**Proposed decisions**
- The app gate treats a domain or data file whose every executable line is removed by ignore-start/end or ignore-line markers like a `coverage:ignore-file` marker (fails unless allowlisted). Extends the 2026-10-12 app gate entry.
