**Correction to AC8 ("about 2 kB")**: 1.84 kB is what a warm builder sends: BuildKit transfers only files it has not seen. On a new builder the real context is 86.86 kB, which is the size of the allowlisted files (84,741 bytes of content plus tar headers); the tracked repo is 1,176,304 bytes plus .git, so the ignore file clearly applied. Both numbers appear in the logs: the first build on a fresh runner shows 86.86 kB, the cached loads show 1.84 kB. A fixed 10 kB limit would only have passed because of the warm builder, so the last step builds on the Docker engine's own builder (which has never seen the context) and checks the transfer against the allowlisted size plus 25% and 16 kB: `allowlisted files: 84741 bytes; whole repo: 1176304 bytes; context limit: 121926 bytes`, `ok: build context 86.86kB`. The limit follows the code as it grows.

#### Should fix

- **R1-S1** server.yml:49-51 and :199-229. No `pipefail`. Without an explicit `shell:`, GitHub runs `bash -e {0}`, so pipelines report only the last command. In the context check, `grep ... | tail -n 1 | awk '...'` has no END block: if grep found nothing, awk reads no lines and exits 0. Today the bare `grep "transferring context" nosha.log` on line 220 happens to fail the step first, but deleting that "log only" line would turn a missing size into a false green. T-014's app.yml sets `defaults.run.shell: bash` (which adds `-o pipefail`) and repeats it in job-level defaults because job defaults replace workflow defaults. Fix: same here (workflow level, and in the `dart` job's `defaults.run` next to `working-directory`), and add `END { if (NR == 0) { print "::error::no transferring context line"; exit 1 } }` to the awk.
- **R1-S2** server.yml:144, 161, 175, 180, 191. `${{ steps.version.outputs.app_version }}` is pasted into run scripts and build args. Its value comes from `server/pubspec.yaml`, which a pull request controls, so a crafted `version:` line becomes shell code. Impact is low (a PR's own tests already run its code with a read-only token and no secrets), but it breaks the T-016 convention in repo.yml of passing values through `env:`. Fix: on the two smoke steps set `env: APP_VERSION: ${{ steps.version.outputs.app_version }}` and use `"$APP_VERSION"`; the `build-args` inputs are not shell and can stay.
- **R1-S3** handoff AC3 row and backend-developer memory. The claim "the line total stayed 181, so files no test imports still count" is not true in general. coverage 1.15.1 `test_with_coverage` reports only libraries loaded in the test isolate and has no option to include unloaded files. The total stayed 181 only because the remaining test imports `package:boardgame_server/boardgame_server.dart`, which exports every src file. A new lib file that is not exported by the barrel and that no test imports would not count, and the gate would not notice. Fix: correct the note, and either add a gate check that every `lib/**/*.dart` (minus `*.g.dart` and `*.freezed.dart`) appears as an `SF:` line in lcov.info, or add a test that imports every lib file.
