**Log retention (AC9)**

The json-file driver rotates by size only; its options are `max-size`, `max-file`, `compress`, and labels/env, with no time-based option (https://docs.docker.com/engine/logging/drivers/json-file/, 2026-10-12). At about 150 bytes per request line, an idle server writes about 2,900 health check lines a day (about 0.4 MB), so 3 x 10 MB holds roughly two months, longer than the 7-day target [ASSUMPTION]. Logs disappear only when the container is removed. So a time-based rule is needed for production. Options for T-071:

1. Docker's `journald` driver on the VM plus journald `MaxRetentionSec=7day` (and `MaxFileSec=1day`, so whole journal files age out daily). journald docs: MaxRetentionSec "controls whether journal files containing entries older than the specified time span are deleted", default 0 = off (https://man7.org/linux/man-pages/man5/journald.conf.5.html). `docker logs` still works with journald (https://docs.docker.com/engine/logging/drivers/journald/). Needs host configuration, so it belongs in T-071. My recommendation.
2. Keep json-file and recreate the server container weekly (`up -d --force-recreate server`): a few seconds of downtime, and it deletes all older logs at once.
3. Accept size-only rotation and change the target. Needs the user.

**Proposed decisions**

1. Local and production stack use `postgres:18.6-alpine3.24` and `caddy:2.11.7-alpine`, pinned by index digest; upgrades change tag and digest together.
2. The server's Compose health check is `/app/server --healthcheck` every 30 s (timeout 5 s, 3 retries, start period 10 s, start interval 1 s); exit codes 0 healthy, 1 unhealthy, 64 bad arguments.
3. Caddy upstream `keepalive 30s`, HTTP/3 off, no access log.
4. PostgreSQL is never published on the host; local access is `compose exec postgres psql`. The `db` network is internal.
5. The server container runs read-only with all capabilities dropped and `no-new-privileges`; Caddy keeps only `NET_BIND_SERVICE`.
6. Log retention: option 1 above (journald with a 7-day rule) in T-071.
7. `deploy/compose.sh` is the documented entry point for Compose commands that build.

## Open questions

1. (backend-developer) The official postgres and caddy images contain GPL-2.0 and GPL-3.0 OS packages (busybox, bash, readline, gdbm, apk-tools) and LGPL libraries. The rule says MIT, BSD, or Apache 2.0, and the 2026-10-12 exception covers only glibc and the CA bundle in our server image. We run these images unmodified and do not distribute them. Does the user approve them under the same terms (run only on our machines, never republished)? If not, the alternatives are building our own images, which still need a libc and the same kinds of packages, so I see no practical GPL-free option for PostgreSQL.
2. (backend-developer) The 7-day log retention [ASSUMPTION] cannot be met with json-file rotation alone. Which option (journald with MaxRetentionSec, weekly recreate, or a changed target) should T-071 use?
3. (backend-developer) Should the production database be initialized with PostgreSQL's builtin collation provider (`POSTGRES_INITDB_ARGS="--locale-provider=builtin --builtin-locale=C.UTF-8"`), so text indexes do not depend on the OS's libc collation across image upgrades? It only takes effect on an empty volume, so it must be decided before T-071's first start. I did not set it here because I could not finish checking the docs for it in this round.

## Research notes for PM

- Docker json-file logging has no time-based retention option (https://docs.docker.com/engine/logging/drivers/json-file/, checked 2026-10-12). Relevant to the 7-day log retention [ASSUMPTION].
- PostgreSQL 18 images moved PGDATA to `/var/lib/postgresql/18/docker` and the volume to `/var/lib/postgresql` (https://hub.docker.com/_/postgres, checked 2026-10-12). Matters for T-072 backups and restores.
