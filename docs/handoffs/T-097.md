### Recommendation

**Verdict: no viable fallback that keeps the product as specified.** No source offers BGG's mix of coverage, game details, and commercial terms. Board Game Atlas is gone (BGA-01). Wikidata is the only free source with clear commercial terms, and it has about 4,500 board games, roughly 5% of BGG's size, with sparse details (WD-04, WD-08, WD-10). Barcode databases give product titles, not game details, and their terms on public display are unclear, or forbid it in Go-UPC's case (FB-02).

**What to do:**

1. Keep BGG as the primary source and submit the license application as planned (T-087).
2. Now, at no cost: keep the game record independent of BGG ids (proposed decision 2).
3. If BGG refuses: first ask BGG what would change its answer (F1 b).
4. If BGG still refuses and the user wants to continue: build the reduced product below, after the user approves the cost and the data licenses.

**Best partial fallback (reduced product):** our own catalog seeded from a weekly Wikidata dump import (WD-07), one paid barcode database for barcode to title (EAN-Search.org or UPCitemdb, only after the provider confirms in writing that we may show its titles in a public app and cache them), games users add by hand (PRD Q11), and eBay GTIN search (EBAY-42), which keeps current prices working for any scanned barcode.

**What would change, by feature:**

| Feature | With BGG (current plan) | Reduced product |
|---|---|---|
| Barcode lookup | GameUPC returns BGG ids; the backend fetches BGG details. | The barcode database returns a retail title. The backend matches it against our catalog (fuzzy title match, accuracy unknown [ASSUMPTION]), or the user confirms or edits the title. If the user agrees to share, confirmed matches enrich our catalog (PRD Q9). GameUPC helps only for games in Wikidata, and only if counsel agrees (F4). eBay GTIN search still shows prices for the scanned barcode. |
| Title search | BGG search across roughly 85,000 games (WD-08). | Search over our own catalog: about 4,500 Wikidata games plus games users have added. Most niche games are not found, so "Add a game by hand" must sit in the no-results state. |
| Game detail | Name, year, players, play time, designers, publishers, description, and a cover if BGG allows. | Mostly name only. Where Wikidata has them: players (41%), year (32%), publisher (25%), designers (16%), "duration" that may be play time (17%). Description is one line, or a Wikipedia extract (CC BY-SA) for 47%. Cover images almost never; the spec's partial-data and no-image states already handle this (docs/ux/screens/game-detail.md). |
| Attribution | BGG name and "Powered by BGG" logo on every screen with BGG data (BGG-40, BGG-41). | No BGG logo. Optional credit "Game data from Wikidata" (CC0 needs none). Required CC BY-SA credit and license notice wherever Wikipedia text or a Commons image is shown (WD-09, WD-11). Barcode database credit only if its terms require it (unread). The PRD, UX copy, store listings, and the Apple permission proof (APPLE-08, T-094) all change. |
| Prices | Unchanged. | Unchanged. eBay search by GTIN, or by the game's title. |

**Rough effort [ASSUMPTION, PM estimate for one developer each, to be refined by the developers]:**

- Backend: Wikidata dump import job, catalog tables, and catalog title search: about 1 to 2 weeks. Barcode database client with caching: about 2 to 3 days. Removing the BGG client and queue: saves the BGG work not yet done.
- App: "Add a game by hand" flow (partly planned in M3 under Q11), attribution changes, and game detail with mostly missing fields: about 1 week.
- UX and PM: spec, copy, and legal text changes: about 2 to 3 days.
- Total: about 3 to 4 weeks, partly offset by BGG work we would not do.

**Cost and approvals needed:**

Go-UPC (from $74.95) is rejected on its terms (FB-02). GS1 US (from $6,500 a year) is rejected on cost (FB-06).

- F4. Some Wikidata statements cite BGG as their source (WD-05), and GameUPC works through BGG ids. If BGG has refused us, should a lawyer confirm that using Wikidata board game data and BGG ids as a lookup key is safe? [ASSUMPTION: low risk, not legal advice.]
- F5. Should the GameUPC email (T-088) also ask whether GameUPC can return a product title it holds itself, not taken from BGG? That would help path (c), but it is unknown whether GameUPC stores titles independently of BGG.

## Proposed decisions

For the orchestrator to record in docs/decisions.md if the user accepts:

1. No researched source can replace BGG with the product as specified. BGG stays the primary data source, and the license application goes ahead as planned. Reason: docs/api-research.md section 10.9 and B11.
2. Keep our data model independent of BGG ids: games get our own id, with the BGG id as one optional external id next to a GTIN list and an optional Wikidata id. Reason: lets a fallback catalog work without a schema change if BGG refuses or ends the license (BGG-15). This affects the api_contract and backend tickets; the PRD owner should add it.
3. No fallback build work until BGG answers. If BGG refuses, the PM writes a PRD change for the user to approve, based on F1 to F5. Reason: every fallback path changes what users see and may cost money.
